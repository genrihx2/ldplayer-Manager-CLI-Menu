# LDManager v2.0.7

Изменения с v2.0.6.

## Изменения

- Исправлено: автообновление падало с `404 (Not Found)`. Адрес файла собирался с пустым ref (`…/repo//LDManager.ps1`), потому что `$script:ReleaseTag` нигде не заполнялась — функция `Get-ReleaseTag` была описана, но ни разу не вызывалась.
- Файлы обновления качаются с того же тега, чей `SHA256SUMS` проверяется (или из ветки `main`, если манифеста нет): загрузка и сверка хешей больше не расходятся.
- Защита от отката: если GitHub считает «latest» прошлый релиз (так вышло с v2.0.5, опубликованным позже v2.0.6), обновление берёт `main`, а не перезаписывает свежую копию старым кодом.
- Манифест от другого релиза больше не принимается: сверка идёт только когда качаем ровно тот релиз, откуда взят `SHA256SUMS`; иначе пишется «без сверки (манифест от другого релиза)».
- Сообщение при несовпадении хешей теперь называет релиз манифеста и фактический ref загрузки.
- Тесты: 3 новых Pester-теста на выбор ref для скачивания (текущий тег / старый релиз / нет манифеста).

## Обновление

> ВАЖНО: в версии 2.0.6 автообновление не работает (ошибка 404). Обновитесь ОДИН раз вручную — скачайте ZIP ниже и замените `LDManager.ps1`, `LDManager.core.ps1`, `LD.Sieve.ps1`. Дальше пункт `[u]` работает как обычно.

Вариант 1 — вручную: скачайте ZIP релиза и замените `LDManager.ps1`, `LDManager.core.ps1`, `LD.Sieve.ps1`.

Вариант 2 — в самом меню: `[u] Обновить LDManager` (или `[g] GitHub → [3] Автообновление скрипта из GitHub`) — уже после ручного обновления.

> После замены файлов, если включена строгая политика выполнения (AllSigned), подпишите скрипты заново через меню `[s]`.
