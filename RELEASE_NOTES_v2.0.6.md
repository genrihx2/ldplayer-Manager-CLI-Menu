# LDManager v2.0.6

Изменения с v2.0.5.

## Изменения

- Проверка SHA-256 по манифесту SHA256SUMS: при обновлении скачанные файлы сверяются с манифестом последнего релиза, и при несовпадении запись отменяется — файлы на диске не трогаются, показываются ожидаемый и полученный хеши.
- Новый пункт [g] GitHub → [6] Проверка целостности файлов: сверяет то, что GitHub отдаёт прямо сейчас, с манифестом (ОК / РАСХОЖДЕНИЕ / нет в манифесте) и отдельно сравнивает локальную копию с репозиторием по содержимому.
- SHA256SUMS в релизах теперь пофайловый: воркфлоу считает хеши .ps1 из raw.githubusercontent.com по тегу, а не из рабочей копии с CRLF.
- Локальные копии сравниваются по содержимому без блока подписи: переподписанный у себя файл не считается подменой.
- Исправлено: ассет SHA256SUMS отдаётся как application/octet-stream, и Invoke-WebRequest возвращал в .Content массив байт — манифест не распознавался.
- Новый пункт [u] Обновить LDManager в главном меню — обновление в один шаг, без захода в [g] GitHub.
- Автообновление стало подробнее и безопаснее: дата изменения локальной копии, построчный отчёт «обновлён / без изменений», проверка версии в скачанном ядре, предложение перезапустить скрипт.
- Лечение битой копии: при совпадении версий предлагается перекачать файлы заново.
- [v] Информация о версиях показывает дату изменения файлов и папку скрипта.
- Исправлено: в LDManager.core.ps1 функция Show-GithubMenu была определена дважды — второе определение перетирало первое.
- Добавлены тесты Pester для Sieve (tests/Sieve.Tests.ps1) и workflow CI со сканированием кода.

## Обновление

Вариант 1 — в самом меню: [u] Обновить LDManager (или [g] GitHub → [3] Автообновление скрипта из GitHub).

Вариант 2 — вручную: скачайте ZIP релиза и замените LDManager.ps1, LDManager.core.ps1, LD.Sieve.ps1.

> После замены файлов, если включена строгая политика выполнения (AllSigned), подпишите скрипты заново через меню [s].
