# LDManager v2.0.10

Изменения с v2.0.9.

## Изменения

- **Критично: автообновление записывало файлы с двойным BOM**, после чего скрипт не запускался вообще:

  ```
  C:\test\LDManager\LDManager.ps1:15:1
  Непредвиденный атрибут "CmdletBinding".
  ```

  Причина: содержимое из сети уже начинается с символа `U+FEFF`, а запись шла через `UTF8Encoding($true)`, который добавляет BOM ещё раз. Теперь запись идёт через `Write-ScriptFileContent`, которая всегда оставляет ровно один BOM.
- Неизменённые файлы больше не перезаписываются: сравнение идёт по нормализованному содержимому (без BOM и без блока подписи), поэтому одинаковый код не считается новым и подпись не теряется зря.
- Тесты: два Pester-теста на запись файла (содержимое с BOM и без — на диске ровно один BOM).

## Обновление

> Если ваши файлы уже получили двойной BOM, скрипт не запустится и обновиться сам не сможет — замените `LDManager.ps1`, `LDManager.core.ps1`, `LD.Sieve.ps1` из ZIP этого релиза (или удалите лишний BOM).

Вариант 1 — вручную: скачайте ZIP релиза и замените `LDManager.ps1`, `LDManager.core.ps1`, `LD.Sieve.ps1`.

Вариант 2 — в самом меню: `[u] Обновить LDManager`.

> После замены файлов, если включена строгая политика выполнения (AllSigned), подпишите скрипты заново через меню `[s]`.
