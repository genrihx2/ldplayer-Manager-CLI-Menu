# LDManager v2.0.1

Патч-релиз: исправлены две ошибки, из-за которых не работали автообновление и список инстансов.

## Исправлено

### 1. «Проверить обновления» / «Автообновление» всегда сообщали об ошибке
`Get-RemoteScriptVersion` искал строку версии `$script:ScriptVersion = 'X.Y.Z'` в файле `LDManager.ps1`, хотя она задаётся в `LDManager.core.ps1`. Проверка всегда завершалась сообщением «Не удалось получить версию из GitHub (нет сети или репозиторий недоступен)», даже когда сеть была в порядке.
Теперь версия читается из `LDManager.core.ps1` (с запасным вариантом чтения точки входа — для совместимости со старыми копиями).

### 2. Список инстансов пуст, команды запуска открывали окно GUI
`Resolve-LDConsolePath` принимал значение `DisplayIcon` из реестра за путь к `ldconsole.exe`. У LDPlayer 14 `DisplayIcon` указывает на `dnplayer.exe` (графический интерфейс), поэтому все команды уходили в GUI: `list2` не отвечал, «Available instances» оставался пустым, а пункт «Запустить инстанс» открывал окно эмулятора.
Теперь из реестра берётся `ldconsole.exe` из папки установки; сохранённый в конфиге неверный путь тоже исправляется автоматически. Также обновлённая версия сообщает точную причину, если версию проверить не удалось.

### 3. Самообновление обновляет все файлы
Раньше заменялся только `LDManager.ps1`, а ядро и интеграция Sieve оставались старыми. Теперь обновляются все три файла, резервные копии складываются в папку `LDManager.backup_<дата>`.

### 4. Самодиагностика пути при старте
Если в конфиге сохранён путь не на `ldconsole.exe` (например, `dnplayer.exe`), главное меню и настройки показывают жёлтое предупреждение вместо молчаливого неработающего пути.

### 5. Исправлена подпись скрипта (пункт [s])
Сертификат теперь помещается в доверенные корни (Root) и издателей (TrustedPublisher) текущего пользователя — раньше попадал только в TrustedPeople, и подпись возвращала UnknownError («цепочка обработана, но прервана на корневом сертификате»). Подписываются все три файла скрипта (для режима AllSigned) с меткой времени.

### 6. Диагностика доступа к GitHub
Новый пункт меню `[g] GitHub → [5]`: проверяет `api.github.com` и `raw.githubusercontent.com` по шагам (DNS → TCP 443 → HTTPS) и называет точную причину сбоя вместо общего «нет сети»; коды 403 (лимит запросов) и 404 поясняются отдельно. Ошибки проверки обновлений («Проверить обновления», «Автообновление», «Информация о версиях») теперь тоже сопровождаются точной причиной: HTTP-код, лимит запросов, отсутствие файла или сетевая ошибка.

## Прочее

- Добавлен `.env.example` и раздел «Секреты в Infisical» в README; `.env` добавлен в `.gitignore`.
- Pester-тесты: 29/29.

### 7. Детекция запущенных инстансов (LDPlayer 14)
`runninglist` в LDPlayer 14 отдаёт просто имя инстанса без полей — старый парсер его отбрасывал, и запущенный инстанс помечался остановленным: ADB-меню отказывало с «Инстанс не запущен». Теперь поле «Android запущен» из `list2` — главный признак, `runninglist` — дополнительный.

### 8. Идентификация инстанса читается из JSON-конфига (LDPlayer 14)
Меню идентификации искало только классический `vms\leidianN\config.ini`, которого LDPlayer 14 не создаёт, и показывало «Не удалось найти config.ini». Значения на самом деле лежат в `vms\config\leidianN.config` (ключи `propertySettings.*`) — теперь они читаются оттуда.

### 9. Root-переключение подтверждается по конфигу
После `modify --root` меню читает `basicSettings.rootMode` обратно из конфига инстанса и печатает фактический результат (ВКЛЮЧЁН/ВЫКЛЮЧЕН) с пояснением, что переключатель в окне LDPlayer обновится после перезапуска GUI.

### 10. Исправлен крах «Информации о версиях»
`$PSCommandPath` пуста при загрузке ядра через точку входа — `Show-VersionInfo` передавала пустую строку в `Get-AuthenticodeSignature` и падала с «Cannot bind argument to parameter 'FilePath'». Путь теперь строится от `$scriptRoot`.

## Обновление

Вариант 1 — в самом меню: `[g] GitHub → [3] Автообновление скрипта из GitHub` (в версиях ≤ 2.0.0 этот пункт показывает ошибку — используйте вариант 2).

Вариант 2 — вручную: скачайте ZIP релиза и замените `LDManager.ps1`, `LDManager.core.ps1`, `LD.Sieve.ps1`.

> После замены файлов, если включена строгая политика выполнения (AllSigned), подпишите скрипты заново через меню `[s]` — self-signed сертификат появится автоматически.
